# Optional V8 embedding foundation

The official V8 repository is pinned as submodule `thirds/v8` at
`06637ec79e440fad8831624d2ccd3175f2495b0d` (headers report 15.9.0 candidate).
Normal TRECH builds still use QuickJS. V8 is not built by CMake and is not a selectable hook
backend yet. No performance or numerical-equivalence claim follows from this checkout.

An opt-in `trech-v8-probe` C++ target compiles a pure script, executes it, creates a trusted
in-process V8 code cache, consumes that cache in a fresh context and checks identical JSON
completion results. With no arguments it checks a fixed arithmetic example; with a filename it
uses that script's completion value. It supplies no TRECH host functions, inference, Geant4
access or subprocess management. Code caches are V8-version/build-specific, not portable JS
bytecode and not a substitute for runtime parity.

V8 needs its upstream depot_tools/GN/Ninja workflow and dependencies. Follow its official
[source build guide](https://v8.dev/docs/build) and [embedding guide](https://v8.dev/docs/embed).
Build the pinned revision's `v8_monolith` before enabling the TRECH target. An example starting
GN configuration for a standalone native build is:

```text
is_debug=false
is_component_build=false
v8_monolithic=true
v8_use_external_startup_data=false
v8_enable_i18n_support=false
v8_enable_pointer_compression=false
v8_enable_sandbox=false
```

Use the upstream host/target toolchain settings appropriate for your machine. Keep generated
artifacts in `thirds/v8/out.gn/trech` or under `build/`; never commit them. This heavy upstream
build was not performed as part of the initial foundation. Syntax compilation of the TRECH
probe against the pinned headers was checked; linking/execution remains unvalidated.

```sh
cmake -S . -B build/v8-probe -G Ninja \
  -DTRECH_ENABLE_GEANT4=OFF -DTRECH_ENABLE_V8_PROBE=ON \
  -DTRECH_V8_BUILD_DIR=thirds/v8/out.gn/trech
cmake --build build/v8-probe --target trech-v8-probe
ctest --test-dir build/v8-probe -R trech_v8_code_cache --output-on-failure
```

`TRECH_V8_BUILD_DIR` must point to the build directory containing `obj/libv8_monolith.a`
(use an absolute CLI value if configuring outside the source directory). If the V8 build uses
pointer compression or sandboxing, set `TRECH_V8_DEFINITIONS` to the matching ABI definitions;
do not link headers with flags inconsistent with the library. Missing archives fail configuration
instead of silently fetching or switching engines.

Next steps are an engine-neutral JS host boundary, all TRECH globals/hooks/model operators,
seed/RNG/emit/provenance parity, reset/lifetime/error tests, same-input differential runs and
repeatable end-to-end benchmarks. Training remains optional offline tooling. Persisted code
caches need source/build/flags identities and rejection handling before use in normal runs.

# Optional V8 embedding foundation

The official V8 repository is pinned as submodule `thirds/v8` at
`06637ec79e440fad8831624d2ccd3175f2495b0d` (headers report 15.9.0 candidate).
Normal TRECH builds still use QuickJS. V8 is not built by CMake and is not a selectable hook
backend yet. No performance or numerical-equivalence claim follows from this checkout. A V8
host can already evaluate `Math.*` bit for bit like QuickJS through
[`js/trech_dmath_v8.js`](#deterministic-math-in-v8-jstrech_dmath_v8js).

The separate [atomic research tool](../research/atomic_stability.md) executes its JS numerical core on an
already-installed **Node.js/V8**, with an opt-in `trech-atomic` C++ process launcher. It neither
embeds this pinned V8 revision nor provides TRECH hook parity. `TRECH_ENABLE_ATOMIC_RESEARCH`
defaults OFF and requires Node >=18; no upstream V8 build is triggered. Its report records
the actual Node/V8 versions, rather than attributing execution to the unbuilt submodule.

An opt-in `trech-v8-probe` C++ target compiles a pure script, executes it, creates a trusted
in-process V8 code cache, consumes that cache in a fresh context and checks identical JSON
completion results. With no arguments it checks a fixed arithmetic example; with a filename it
uses that script's completion value. It supplies no TRECH host functions, inference, Geant4
access or subprocess management. Code caches are V8-version/build-specific, not portable JS
bytecode and not a substitute for runtime parity.

V8 needs its upstream depot_tools/GN/Ninja workflow and dependencies. Follow its official
[source build guide](https://v8.dev/docs/build) and [embedding guide](https://v8.dev/docs/embed).
Build the pinned revision's `v8_monolith` before enabling the TRECH target. An example starting
GN configuration for a standalone native build is:

```text
is_debug=false
is_component_build=false
v8_monolithic=true
v8_use_external_startup_data=false
v8_enable_i18n_support=false
v8_enable_pointer_compression=false
v8_enable_sandbox=false
```

Use the upstream host/target toolchain settings appropriate for your machine. Keep generated
artifacts in `thirds/v8/out.gn/trech` or under `build/`; never commit them. This heavy upstream
build was not performed as part of the initial foundation. Syntax compilation of the TRECH
probe against the pinned headers was checked; linking/execution remains unvalidated.

```sh
cmake -S . -B build/v8-probe -G Ninja \
  -DTRECH_ENABLE_GEANT4=OFF -DTRECH_ENABLE_V8_PROBE=ON \
  -DTRECH_V8_BUILD_DIR=thirds/v8/out.gn/trech
cmake --build build/v8-probe --target trech-v8-probe
ctest --test-dir build/v8-probe -R trech_v8_code_cache --output-on-failure
```

`TRECH_V8_BUILD_DIR` must point to the build directory containing `obj/libv8_monolith.a`
(use an absolute CLI value if configuring outside the source directory). If the V8 build uses
pointer compression or sandboxing, set `TRECH_V8_DEFINITIONS` to the matching ABI definitions;
do not link headers with flags inconsistent with the library. Missing archives fail configuration
instead of silently fetching or switching engines.

## Same-input differential (QuickJS vs installed Node/V8)

`scripts/js_engine_differential.py` runs one scenario's top-level JavaScript in TRECH's QuickJS
host (`trech inspect`) and in a minimal Node/V8 host (`scripts/js_engine_differential_node.js`:
`TRECH_INCLUDE`/`TRECH_READ_JSON` only, no native host functions, hooks or Geant4) and compares the
results bit for bit. The probe `tests/fixtures/js_engine_differential/probe.js` records Math
builtins on a fixed grid, `js/trech_random.js` streams and 40 mW water MD steps with CHILL+
phases, every double as its IEEE-754 bits.

```sh
python3 scripts/js_engine_differential.py --trech build/dev/trech --json build/js_diff.json
```

Recorded 2026-11-16, platform libm: QuickJS and Node 24.21.0 / V8 13.6.233.17 on macOS ARM64
disagreed on 1 to 19 of 48 grid points for 15 of 20 Math builtins, always by 1 ulp; 2 of 32
Box-Muller gaussians differed, and after 40 mW steps 61/96 x positions differed (up to 352 ulp).

Recorded 2026-11-16, after QuickJS switched to TRECH's deterministic host math (`trech_dmath`,
fdlibm-derived, no FMA contraction; see the
[runtime handbook](../../AGENTS/engine/runtime/AGENTS.md#deterministic-host-math--trech_dmath-srcjsdeterministicmathc--deterministicmathh)):
18 of 20 builtins and all 32 gaussians are bit-identical on the grid, and after 40 mW steps 3 of
288 coordinates differ by 1 ulp (CHILL+ phases and temperatures agree). The engines are still
**not** bit-identical, for reasons on the V8 side: Node 24 defaults to `--use-std-math-pow`
(the platform `pow`; 7 grid differences, 3 with `--no-use-std-math-pow`), V8's `Math.hypot` uses
its own scaled-sum algorithm (16 differences), and Node's arm64 build fuses multiply-add inside
V8's fdlibm, which flips the last bit of e.g. `exp` on about 0.03% of inputs (the remaining mW
differences persist with legacy `pow`). A contraction-enabled build of `trech_dmath` matches
Node's `Math.*` bit for bit for 15 functions on 50 000 inputs, so the algorithms are V8's
fdlibm. A V8 backend reaches byte replay only by installing `trech_dmath` as its Math and `**`.
CTest `trech_js_engine_differential` gates only the portable properties (integer stream,
`sqrt`, phases, builtins within 1 ulp) and reports the rest.

## Deterministic Math in V8 (`js/trech_dmath_v8.js`)

V8 hosts can now compute `Math.*` with exactly the code QuickJS uses. The C library
`trech_dmath` is compiled to a small WebAssembly module, which `js/trech_dmath_v8.js` installs
as `Math.*`:

```js
const dmath = require('./js/trech_dmath_v8.js');
dmath.install(Math);   // or the Math object of a node:vm context
Math.exp(1);           // same bits as QuickJS: 0x4005bf0a8b145769
```

Why WebAssembly works: its 64-bit floating-point add, subtract, multiply, divide and square
root are each one correctly rounded IEEE-754 operation, and WebAssembly has no fused
multiply-add. The module therefore returns the same bits on every CPU that V8 runs on,
whatever the host C compiler would do. The installed wrappers repeat QuickJS's JavaScript
special cases: arguments go through ToNumber in order, `Math.pow(±1, ±Infinity)` and
`Math.pow(±1, NaN)` are NaN, and `Math.hypot` folds its arguments pairwise. `sqrt`, `abs`,
`floor` and the other exact functions keep V8's own, which IEEE-754 already defines bit for bit.

What to know before relying on it:

- **`**` is not covered.** JavaScript cannot replace an operator, so in V8 `x ** y` still uses
  V8's pow. Write `Math.pow(x, y)` where results must replay across engines.
- **It costs time.** In a JIT-compiled loop of `exp`, `sin`, `log` and `pow` on macOS arm64
  (Node 24.21.0), V8's builtins take 6.4 ns per call and the installed module 24 ns. The
  QuickJS host takes 51 ns per call for the same loop.
- **The module is generated.** `js/trech_dmath_wasm_data.js` records the SHA-256 of the C source
  and header it came from. CTest `trech_dmath_wasm` fails if either changes; regenerate with
  `python3 scripts/build_dmath_wasm.py` (needs Emscripten's `emcc`; `--check` confirms that the
  committed module is reproduced byte for byte). Using the module needs only Node.

The same test recomputes the 22 golden digests of `tests/test_deterministic_math.cpp` (4096
inputs per function) inside V8 and checks them against the C values.

With `--dmath`, the differential installs the module in its Node context first:

```sh
python3 scripts/js_engine_differential.py --trech build/dev/trech --dmath --check --require-identical
```

Recorded 2026-11-21 (macOS arm64, Node 24.21.0 / V8 13.6.233.17): **bit-identical**. All 20
builtins, 32 gaussians, 96 CHILL+ phases and all 288 coordinates after the 40 water steps
match QuickJS, where V8's own Math left 23 builtin and 3 coordinate differences. CTest
`trech_js_engine_differential_dmath` gates this identity. It is still Node's V8, not the pinned
submodule, and still top-level evaluation without TRECH host functions. An embedded V8 backend
must install this module, or link `trech_dmath` natively, before running any scenario code.

Next steps are an engine-neutral JS host boundary, all TRECH globals/hooks/model operators,
seed/RNG/emit/provenance parity, reset/lifetime/error tests, same-input differential runs and
repeatable end-to-end benchmarks. Training remains optional offline tooling. Persisted code
caches need source/build/flags identities and rejection handling before use in normal runs.
